# Agent Note: 结果区折叠与时间线分页

Status: implemented

## Problem

一次生成最多 10 张，全部铺开要占两屏；历史任务又会一直往上堆，主界面滚动条越滚越细（用户原话：「不然主界面滚动条越来越小」）。
第一版用文字按钮「查看全部 10 张（还有 6 张）」解决溢出，被判「太丑」——它占一整行、和卡片信息行的排版语言打架。

## Decision

呈现分成两层，互不干扰：

1. **外观设置**新增「结果区默认显示行数」（1–3，默认 2），与主题 / 配色 / 密度同存于 `image-agent:appearance:v1`（`Appearance.resultRows`）。
2. **单个任务组**默认只显示 `列数 × resultRows` 张。超出时网格底部出现一个淡玻璃圆形徽章（`⌄ +N`，N 是没显示的张数）；点一次展开全部，再点收回默认行数。徽章不是文字按钮：背景是文字色 9%、`blur(14px)`、无阴影，压在图片上不抢注意力。
   判定点只有一个 `hasMore = visibleCount < total`（`ResultGroup` 内）：为真时徽章显示 `⌄ +N`、点击 `extra += PAGE_SIZE`；为假时显示 `收起`、点击 `extra = 0`。标题栏里那个上箭头是同一动作的冗余入口，用于展开后底部徽章滚出视野的情况。
3. **时间线**（主界面结果列表）默认只渲染最近 10 个任务，列表末尾给「加载更早的 10 个任务（还有 N 个）」，每点一次 +10。

## 机制不变量

这些是踩过坑换来的，改动时必须守住：

- `max-height` **never** 在 `px` 与 `none` 之间切换。两端都必须是像素值，否则不可插值、直接瞬跳。踩坑现场：展开时把 `maxHeight` 设成 `undefined`，展开看着正常，收起完全没有动画。
- 卡片 **never** 按可见数 `slice()` 裁剪 DOM。DOM 里的卡片一减少，`scrollHeight` 立刻变成新高度，收起目标值与当前值相同，过渡消失。正确做法是全部渲染、只靠 `max-height` 裁。
- 行高 **must** 由 `useLayoutEffect` 实测第一张卡的 `offsetHeight`，不能写死：字号（12–18px）和密度都可调，写死会在改设置后错位。
- 时间线是「新的在上」（按 `createdAt` 降序），分页取**前** N 个；写成 `slice(-N)` 会翻出最老的一批任务。
- 徽章图标的位移 **must** 加在外层 `<span>` 上：`ChevronDownIcon` 自带 inline `transform: rotate()`，写在 `svg` 上的 CSS `translateY` 会被 inline 样式覆盖。

## Alternatives considered

- **文字按钮「查看全部 N 张（还有 M 张）」**：最强理由是信息最完整，用户一眼知道总量。但它整行占位、和每张卡片下方的「768×768 / 详情」撞排版，被明确否掉。最终保留信息量（`+N`）但换成圆形徽章，占用减半。
- **一个布尔量一次性展开全部**：实现最简单，代码量最少。但 10 张同时铺开正是「滚动条变细」的成因，等于没解决问题。
- **用 CSS `grid-template-rows` 做行数动画**：语义最贴切（直接表达「显示几行」）。但列数由 `auto-fill` 随窗口宽度变化，行数得靠 JS 反推，动画收益不如 `max-height` 直观，放弃。
- **时间线新任务插到列表底部、保持滚动位置**：能让新结果紧贴输入框，但会改掉「新的在上」这个既有结构，改动面覆盖整个结果区，本次不做。
- **组内也做「每次 +10」分页**：想做，但单任务张数上限就是 10（`invalid-request：生成数量必须在 1–10 之间`），没有第二个 10 可加载。若将来放宽上限再说。

## Consequences

- 收益：默认视图稳定在 2 行，任务再多滚动条也不会细到抓不住；展开/收起双向可逆且都有 260ms 过渡；徽章只留「箭头 + 数字」，视觉噪音比文字按钮低。
- 代价 1：卡片全部渲染（只裁不删），一个 10 张组的 DOM 节点比「只渲染可见」多几倍。因为单任务上限 10 张，这个代价可控。
- 代价 2：`visibleCount`（React 状态）和「实际看到多少」由 `max-height` 决定，两套算法必须用同一份行高换算才一致——换算就在 `ResultGroup` 的 `clampedHeight` 这个 `useMemo` 里（`rows × cardHeight + (rows-1) × 12`）。改行高、改间距、改列数算法时只改这一处，别在别处再写一遍。
- 代价 3：徽章的图文对齐是像素级调出来的（图标 `translateY(0.45px)`），改字号或徽章内边距后需要重新量。
- 遗留：组内分页、以及「新结果贴底」都还没做。

## Testing

- 折叠动画不靠肉眼验收：用 CDP 逐帧采样 `getBoundingClientRect().height`，实测展开 `240 → 536 → 686 → 729 → 741 → 744`、收起 `744 → 448 → 304 → 257 → 243 → 240`。
- 图文对齐用 6 倍放大截图的亮像素包围盒比中心：图标 195.0 / 文字 196.0（差 1px@6x ≈ 0.17 CSS px）。
- 多图场景靠 driver-only 开关 `IMAGE_AGENT_FAKE_LIMIT` 放大假服务上限（只在 `IMAGE_AGENT_SMOKE_DRIVER=1` 时生效，正式运行仍是 4 张；单任务总张数仍受 1–10 校验限制）。
- `npm run smoke` 109 条断言覆盖侧栏 / 结果区 / 设置主路径。结果区「图片真的解码出像素」偶发失败是本仓库既有的 flake（改动前后都出现过），与折叠逻辑无关。
